# Timetable Toolkit for XJTLU Students v0.3.1

v0.3.1 removes obsolete GeoIP metadata throughout the application, publishes
the patched build dependency already adopted on `main`, and includes the
deployment-neutral legal-notice routing introduced after v0.3.0.

## Privacy and access logs

- Login and iCal access logs no longer contain city, network-organization, or
  GeoIP-provider fields.
- The upgrade migration deletes historical values in those fields and drops
  the GeoIP cache, including any complete IP addresses retained there.
- Access history continues to retain the security fields used by the product:
  complete and prefixed IP addresses, trusted-proxy country codes, user-agent
  strings, timestamps, and account relationships. The normal 30-day access-log
  retention remains unchanged.
- Administration filters, user-visible iCal history, and personal-data exports
  now match the reduced schema.

The application does not contact a third-party GeoIP provider. Operators whose
privacy notices still describe city or network-organization enrichment, GeoIP
cache storage, or GeoIP providers as recipients should update those notices to
match their actual deployment.

## Security

The frontend workspace pins the build-time `nanoid` dependency to 3.3.17,
which fixes CVE-2026-67213. The affected package remains part of the frontend
build toolchain and is not copied into the PocketBase runtime image.

## Upgrade

Back up the current PocketBase data before upgrading, then use the supported
upgrade command:

```bash
./self-host.sh upgrade v0.3.1
```

Existing v0.3.0 installations must keep a valid `ACCOUNT_BLOCK_HMAC_KEYS`
configuration. No new environment variable is required by this release.

## Rollback

The GeoIP migration intentionally discards stored metadata. The self-host
upgrade command creates a pre-upgrade database backup and automatically restores
the previous image and data if the upgrade fails.

For a manual rollback after a successful migration, restore the matching
pre-upgrade database backup and previous immutable image together. Reverting
only the image cannot reconstruct deleted fields or cached data.
