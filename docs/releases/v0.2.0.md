# XJTLU Timetable v0.2.0

v0.2.0 is the first release with a formally supported third-party self-hosting
path. It is an early stable release interface, not a 1.0 compatibility promise.

## Highlights

- Deploy a pinned `v0.2.0` image without building on the target server.
- Pull the same multi-architecture image on `linux/amd64` and `linux/arm64`.
- Complete a fresh installation with `./self-host.sh init`.
- Validate an installation with `./self-host.sh check`.
- Back up and explicitly upgrade with automatic rollback on failed health or
  database-integrity checks.
- Configure instance identity, operator contact, source URL, registration
  policy, current semester, and the first invitation at runtime.
- Use documented Caddy or Nginx Proxy Manager HTTPS proxy examples without
  exposing PocketBase directly to the public network.

## Supply-chain artifacts

The release workflow publishes:

- `ghcr.io/geniuslv2006/xjtlu-timetable:v0.2.0` for `linux/amd64` and
  `linux/arm64`;
- BuildKit provenance and an SBOM attached to the GHCR image;
- the immutable image digest in the self-host bundle;
- `xjtlu-timetable-self-host-v0.2.0.tar.gz`; and
- a SHA-256 checksum for the bundle.

No floating `latest` tag is published.

## Installation

This is the first supported third-party self-host release, so deploy it as a
fresh installation by following `docs/SELF_HOSTING.md`:

```bash
cp .env.example .env
chmod 600 .env
./self-host.sh init
```

Do not run `./self-host.sh upgrade v0.2.0` on an existing `v0.2.0`
installation; the command intentionally rejects the already configured
version. Future release notes will identify the supported source version and
the exact upgrade command. The lifecycle tooling already includes complete data
backup, health and integrity checks, and automatic failed-upgrade rollback for
those future transitions.

## Official instance

The official deployment remains separate from the public release channel. It
continues to deploy exact reviewed `main` commit images through the maintainer
workflow. The production VPS only backs up, pulls, migrates, and runs images; it
does not build them.

## Security

Fresh installations start with registration closed, invitation codes required,
and iCal rate limiting and anomaly controls enabled. This release passed the
repository backend and frontend tests, production build, dependency audit,
CodeQL analysis, upgrade and rollback tests, and Trivy image scan before
tagging.
