# Timetable Toolkit for XJTLU Students v0.2.1

v0.2.1 is a privacy and consent-recording patch for both supported self-hosted
installations and the project-operated instance.

## Highlights

- Keep account email addresses private from unrelated authenticated users.
- Remove public timetable visibility while preserving private and friends-only
  schedules.
- Export every supported personal-data category, including security logs,
  invitation records, and legal acceptance history.
- Configure a minimum age and legal-notice version without collecting dates of
  birth.
- Require users to confirm the current requirements and retain immutable,
  server-timestamped acceptance records.
- Open the configured external legal notice from Settings.

## Upgrade

Back up an existing v0.2.0 installation, then upgrade with the supported
self-host lifecycle command:

```bash
./self-host.sh upgrade v0.2.1
```

The migration adds two optional `site_config` fields and a
`legal_acceptances` collection. Generic self-hosted installations retain safe
disabled defaults (`minimum_age = 0` and an empty legal-notice version) until
the operator explicitly configures them.

If an operator enables either requirement, existing users are prompted once
after login. Changing the configured version or age threshold prompts users
again. The application stores only confirmation of the configured threshold;
it does not request or retain a date of birth.

## Project-operated instance

The project-operated deployment validates `https://timetable.xjtlu.uk/privacy`
after application and database health checks complete. This validation confirms
the legal route, Content Security Policy, Cloudflare email obfuscation,
configured legal URL, and application health. A privacy-route failure is
reported without rolling back an otherwise healthy application database.

The instance-specific privacy HTML and reverse-proxy route remain outside this
public release and are backed up in a separate private operations repository.

## Rollback

The self-host upgrade command and project-operated deployment both create a
database backup before applying the migration. Roll back with the documented
backup and previous immutable image if validation fails. Acceptance records are
cascade-deleted when their user account is deleted.
